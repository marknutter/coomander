# Rich Chat Blocks

Coomander's chat pipeline renders non-markdown content inline in an assistant
reply — data **charts** and AI-generated **images** — via a shared
parse/strip/render foundation. The model emits a JSON-carrying marker in its
reply; `apps/web/components/chat-message.tsx` parses it out of the streamed
text with `parseRichSegments` and dispatches it to a React component via
`<ChatBlock>` (`apps/web/components/chat/chat-blocks.tsx`).

## The marker format

```
[CHART:{"type":"bar","title":"Signups","labels":["Jan","Feb"],"series":[{"name":"Signups","data":[12,30]}]}]
[IMAGE:{"key":"ai-images/<userId>/<uuid>.png","alt":"a mountain at sunrise"}]
```

A marker is `[<TYPE>:<json>]` where `<TYPE>` &isin; `CHART | IMAGE`. The payload
is a JSON **object** — and because a chart's `data` arrays contain `]`, a naive
`\[[A-Z_]+:[^\]]+\]` regex mis-terminates at the first inner `]`. Parsing uses a
hand-written, brace-balanced, string-literal-aware scanner instead.

`coomanderChat.ts`'s system prompt (`chatSystemPrompt`, the single source of
truth for the Coomander chat prompt) teaches the model this marker syntax via
the `RICH_CONTENT` block — see [Charts](#charts) and [Images](#images) below.

## The shared pipeline (`@coomander/core/chat/rich-blocks`)

One module (`packages/core/src/chat/rich-blocks.ts`), used on every surface so
they can't drift:

| Function | Used by | Behaviour |
|---|---|---|
| `parseRichSegments(text)` | `chat-message.tsx`'s assistant render path | splits text into ordered `{kind:"text"}` / `{kind:"block", type, json}` segments, each dispatched to `<ChatBlock>` |
| `stripSystemTags(text)` | agents worker persist + `done` frame, web assistant display (pre-segment-split) | strips `[PROFILE:]/[STEP_*:]` system tags but **keeps** block markers |
| `stripAllTags(text)` | user-message echo, **mobile**, **TTS** | strips everything (no block renderer there) |
| `stripTrailingPartialMarker(text)` | web streaming | hides a still-streaming `[CHART:{"ty…` tail so it never flashes as raw text |

**Key invariant:** the agents worker (`apps/agents/src/chat.ts`, via
`stripTags` re-exported from `apps/agents/src/chat-config.ts`) persists
assistant turns and the `done` frame with block markers **intact** (only
system tags are stripped), so a future block renderer can re-render them after
a reload. Mobile and TTS strip everything because neither has a native block
renderer.

## Where each surface consolidates

Before this foundation, tag-stripping was duplicated four times, each with a
slightly different (and in one case, badly broken) regex:

- `apps/web/lib/chat-tags.ts` — `stripTags` now re-exports `stripSystemTags`.
- `apps/web/components/chat-message.tsx` — `ChatMessageContent` uses
  `stripAllTags` for user messages (echo, no blocks) and
  `stripSystemTags(stripTrailingPartialMarker(content))` for the assistant
  path.
- `apps/agents/src/chat-config.ts` — `stripTags` now re-exports
  `stripSystemTags`, consumed by `apps/agents/src/chat.ts`'s persist path and
  `done` frame.
- `apps/mobile/src/app/(app)/index.tsx` — local `stripTags` now delegates to
  `stripAllTags`. Previously this only matched a literal `[TAG:\w+=\w+]`
  pattern and would not have stripped `[CHART:]`/`[IMAGE:]` markers at all.

## The dispatcher (`ChatBlock`)

`apps/web/components/chat/chat-blocks.tsx` exports `ChatBlock`, which
`chat-message.tsx` renders for every `{kind:"block"}` segment. It switches on
`block.type` and renders the matching per-type component, wrapped in a
`BlockErrorBoundary` — a malformed payload (failed `parseChartSpec`/schema
validation, bad JSON, etc.) degrades to a small inline "couldn't render this
content" notice instead of crashing the whole message. A block type with no
renderer wired (or one this build doesn't recognize) falls back to its raw
marker text rather than losing the content — see the `default` case.

Per-type renderers live in their own files so slices stay disjoint: charts own
`apps/web/components/chat/chat-chart.tsx`, images own
`apps/web/components/chat/chat-image.tsx`; neither touches the dispatcher
beyond adding its `case`.

## Charts

`[CHART:{…}]` renders a **recharts** chart (bar/line/pie/area) inline:

```
[CHART:{"type":"bar","title":"Reels this week","labels":["Mon","Tue","Wed"],"series":[{"name":"Shipped","data":[2,1,3]}]}]
```

- **Validation** (`packages/core/src/chat/chart-spec.ts`, exported from the
  `@coomander/core` chat barrel): a Zod `chartSpecSchema`. `type` &isin;
  `bar | line | pie | area`; `labels` are x-axis categories; every series'
  `data` array must align 1:1 with `labels` (cross-field refinement); caps of
  &le;12 series and &le;200 points/series bound abuse. `parseChartSpec(json)`
  never throws — it returns `null` on any failure, and `ChatChart` turns that
  into a thrown error so the `BlockErrorBoundary` shows its fallback.
- **Rendering** (`apps/web/components/chat/chat-chart.tsx`): maps the spec into
  recharts' row shape and renders via the shadcn `ui/chart.tsx` primitives
  (`ChartContainer`/`ChartTooltip`/`ChartLegend`), which inject theme-aware
  `--color-<key>` CSS vars per series so charts track light/dark automatically.
  The first series uses the app's brand `--primary`; additional series cycle a
  small fixed palette.
- **New dependency:** `recharts@3.9.0` (pinned exact, React-19-ready).
- The system prompt instructs the model to chart only real data it has (from
  the conversation or the live ops state) and never fabricate numbers.

## Images

See the `generate_image` tool (`apps/agents/src/tools.ts`) and
`apps/web/components/chat/chat-image.tsx` for AI-generated inline images via
`[IMAGE:{"key":…,"alt":…}]` — R2-backed, auth-scoped storage keys, per-user/day
quota enforced in `POST /api/images`.

## Chat transcript rendering (shadcn components)

The chat page (`apps/web/app/app/chat/page.tsx`) renders the transcript
through shadcn-derived chat components under `apps/web/components/ui/`:
`message-scroller`, `bubble`, `message`, `marker`. These are adapted from
shadcn's June 2026 chat components (Radix variant) and restyled with
Coomander's own Tailwind + semantic tokens — upstream's `cn-*` CSS design
layer ships **empty** in the published `shadcn` package, so the components use
`bg-card`/`text-muted-foreground`/the existing bubble colors instead. Component
names, structure, and `data-*` attributes match upstream for sync legibility;
only the class lists differ. `radix-ui` `Slot` imports are `@radix-ui/react-slot`
(already a direct dep); the shadcn `Button`/`IconPlaceholder` references are
replaced with native buttons / lucide icons (Coomander's `Button` has a
different variant/size API).

**`MessageScroller`** (the headless `@shadcn/react` engine, new pinned dep
`@shadcn/react@0.1.0`, zero runtime deps) replaces the old
`scrollIntoView`-on-every-token loop: it follows the live edge only when the
reader is already at the bottom (scrolling up mid-stream no longer yanks you
back down), opens the thread at its latest turn
(`defaultScrollPosition="end"`), and shows a scroll-to-bottom button.
Wiring: `Provider(autoScroll, defaultScrollPosition="end")` → `Root` →
`Viewport(preserveScrollOnPrepend)` → `Content` → one `Item` per row
(`messageId`, `scrollAnchor` on user turns) → a floating
`Button direction="end"`. Transient rows (the streaming bubble, the "thinking"
spinner, the live voice transcript) are `Item`s **without** `messageId` so the
primitive doesn't register them as addressable.

**`Marker`** renders the connecting/reconnecting status row, paired with the
`shimmer` text-fill animation utility in `globals.css` (gated behind
`prefers-reduced-motion`).

**Coomander has no attachments**, so the shadcn `Attachment` component is
intentionally NOT vendored — Coomander's chat is text/voice/rich-block only.

The WebSocket transport and chat lifecycle (stall/reconnect handling,
optimistic-bubble rollback, `?q=` deep-link seeding) are unchanged — this is a
presentation-only change to how the transcript renders.

## Adding another block type

If adding a new block type beyond `CHART`/`IMAGE`, extend
`BLOCK_MARKER_PREFIXES` + `PREFIX_TO_TYPE` in
`packages/core/src/chat/rich-blocks.ts` (the strip helpers automatically pick
up any prefix in that closed set), add a `case` + renderer component in
`chat-blocks.tsx`, and teach the marker syntax in `coomanderChat.ts`'s
`RICH_CONTENT` prompt block.
